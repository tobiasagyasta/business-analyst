# Financial and Recommendation Standards

Apply `methodology/indonesia-and-currency.md`. All internal financial reasoning and recommendations use `IDR` / `Rp`.

## Financial Reasoning

Use only supplied or cited inputs. Show calculation method, period, currency, units, and whether a cost is fixed, variable, one-time, or ongoing. Label unverified inputs as `ASSUMPTION` and do not calculate false precision.

For material decisions, distinguish revenue, gross margin, contribution margin, operating profit, cash flow, working-capital timing, and capital expenditure. Include base, upside, and downside scenarios when the result is sensitive to uncertain demand, price, cost, or timing. State omitted costs and opportunity costs as limitations.

For financially material decisions, identify practical switch points: the input level at which an option no longer meets a cash, contribution, break-even, payback, financing, or owner-return condition. State the calculation, input range, period, and threshold origin. If evidence is too weak for a meaningful numerical switch point, state that limitation rather than manufacturing precision.

## Proposed Recommendation

A proposed recommendation must:

- Name the option, expected outcome, key trade-offs, and what is deprioritized.
- Cite its supporting decision artifacts and list assumptions that could invalidate it.
- State `HIGH`, `MEDIUM`, or `LOW` confidence with an evidence-quality rationale.
- Specify decision gates, success measures, owner, and review timing when action is proposed.
- For material recommendations, follow `methodology/decision-gates-and-validation.md`: rank decision-changing uncertainties, state gate threshold origins, explain whether validation has positive decision value, name reconsideration conditions, and state a research stop rule.
- Recommend a bounded experiment rather than a permanent commitment when evidence is weak and the decision is reversible.
- Clearly state `PROPOSED RECOMMENDATION`; it is not an approved business decision.
